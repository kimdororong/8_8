# 웹디자인 외주 AI 활용 · 자동화 설계안

대상: AI를 활용해 UI/UX(웹디자인) 외주를 받는 디자이너 팀
목표: 같은 품질을 더 짧은 시간에 내고, 수정 횟수와 분쟁 리스크를 줄인다.
전제: 외부 레퍼런스 MCP(Refero)는 사용하지 않는다. 웹 검색, 고객이 준 자료, 우리 자산(과거 프로젝트)으로 해결한다.

---

## 0. 한 장 요약

| 구분 | 내용 |
|---|---|
| 원칙 | AI는 초안과 반복 작업을 맡고, 판단·책임·최종 품질은 디자이너가 진다 |
| 가장 큰 효과 | ① 브리프 분석과 질문 생성 ② 리서치 요약 ③ 정보구조·카피 초안 ④ 납품 문서 자동 생성 |
| 가장 큰 리스크 | 요구사항 오해로 인한 재작업, 고객 자료 유출, 저작권·AI 사용 고지, 평범한 "AI스러운" 결과 |
| 만들 시스템 | 프로젝트 폴더 규약 + 단계별 프롬프트 모음(스킬) + 검수 봇 + 납품 문서 생성기 + 견적/일정 도우미 |
| 시작 방식 | 한 프로젝트에 1단계(접수~IA)만 적용해 시간 절감을 측정한 뒤 확장 |

---

## 1. 현재 외주 프로세스와 병목 (가정)

실제 팀 상황과 다르면 이 표부터 고쳐서 시작한다.

| 단계 | 일반적 소요 | 병목 원인 |
|---|---|---|
| 문의·견적 | 문의당 1~3시간 | 요구사항이 모호, 견적 근거 부족, 문의 대비 수주율 낮음 |
| 계약·범위 확정 | 1~2일 | 작업 범위·수정 횟수·산출물이 불명확해 나중에 분쟁 |
| 자료 수집·킥오프 | 2~5일 | 고객이 자료를 늦게/흩어서 줌 |
| 리서치 | 1~3일 | 경쟁사·업종 조사에 시간이 많이 듦 |
| 정보구조(IA)·와이어프레임 | 2~4일 | 페이지 구성과 콘텐츠 정의 반복 |
| 시각 디자인(시안) | 3~10일 | 컨셉 탐색, 페이지 수만큼의 반복 작업 |
| 피드백·수정 | 3~10일 | 피드백이 모호하고 수정이 끝없이 이어짐 |
| 납품·핸드오프 | 1~3일 | 스펙 문서·에셋 정리 수작업 |

핵심 통찰: 시간은 디자인 자체보다 **커뮤니케이션(모호한 요구, 모호한 피드백)과 반복 문서 작업**에서 많이 샌다. AI 효과도 여기서 가장 크다.

## 2. 단계별 AI 활용과 자동화

각 단계마다 **입력 → AI가 하는 일 → 산출물 → 사람이 확인할 것** 순으로 정리한다.

### 단계 1. 문의 접수와 견적

- 입력: 고객 문의 메시지, 첨부 자료, 참고 사이트 링크
- AI가 하는 일
  - 문의에서 **프로젝트 유형, 페이지 수, 기능, 일정, 예산 단서**를 구조화해서 추출
  - 빠진 정보를 **되묻는 질문 리스트** 생성 (우선순위 표시)
  - 과거 프로젝트 데이터와 비교해 **작업 시간 범위 추정** 초안
  - 고객에게 보낼 **1차 답장 초안**(질문 포함)
- 산출물: 문의 요약 카드, 질문 리스트, 견적 초안(작업 항목별 시간·비용 범위), 답장 초안
- 사람이 확인할 것: 견적 최종 금액, 우리가 맡을 수 있는 일인지(수주 여부 판단)
- 자동화 포인트: 문의 양식(폼)을 만들어 필수 항목을 미리 받으면 AI 분석 정확도가 크게 올라간다.

### 단계 2. 계약과 범위 확정

- AI가 하는 일
  - 협의된 내용을 **작업 범위서(SOW)** 초안으로 정리: 페이지 목록, 기능, 산출물, 수정 횟수, 일정, 제외 항목
  - **모호한 표현 탐지**: "깔끔하게", "고급스럽게", "적당히" 같은 표현을 찾아 구체 기준으로 바꿔 달라고 질문
  - 계약서에 넣을 **AI 사용 조항**(활용 범위, 고지, 비밀 유지) 초안
- 산출물: SOW 초안, 제외 항목 목록, 변경 요청(추가 비용) 규칙
- 사람이 확인할 것: 계약 문구는 반드시 사람(필요하면 법률 검토)이 최종 확인한다. AI 초안은 참고용이다.
- 효과: 범위 분쟁과 무한 수정을 가장 근본적으로 줄이는 단계다.

### 단계 3. 킥오프와 자료 수집

- AI가 하는 일
  - 고객에게 받을 자료 **체크리스트**(로고, 브랜드 가이드, 텍스트, 이미지, 기존 사이트 접근 권한) 생성
  - 받은 자료를 읽어 **브랜드 요약**(톤, 핵심 메시지, 타깃, 금지 사항) 작성
  - 고객 인터뷰/미팅 녹취를 **회의록 + 결정 사항 + 미해결 질문**으로 정리
- 산출물: 프로젝트 브리프(1페이지), 자료 수집 현황표, 회의록
- 사람이 확인할 것: 브리프를 **고객에게 보내 확인(컨펌)**받는다. 이 컨펌이 이후 분쟁의 기준이 된다.

### 단계 4. 리서치

- AI가 하는 일 (웹 검색 + 고객 제공 자료)
  - 경쟁사·유사 업종 사이트 5~10곳의 **구조, 메시지, CTA, 강점/약점** 비교표
  - 타깃 사용자 **가설 페르소나와 핵심 과업**(Jobs to be done)
  - 업종 특유의 **관행과 규제/필수 요소**(예: 개인정보 처리방침, 결제·환불 고지)
- 산출물: 경쟁사 분석표, 페르소나/과업 문서, 차별화 포인트 제안
- 사람이 확인할 것: 출처 링크로 사실 확인. AI가 틀린 정보를 만들어 낼 수 있으므로 **링크 없는 주장은 사용하지 않는다.**
- 주의: 경쟁사 화면을 모방하지 않고 **패턴과 구조만** 참고한다.

### 단계 5. 정보구조(IA)와 콘텐츠

- AI가 하는 일
  - **사이트맵**과 페이지별 **섹션 구성(와이어프레임 수준 설명)** 제안
  - 사용자 흐름(예: 방문 → 신뢰 확인 → 문의) 설계 초안
  - 페이지별 **카피 초안**(헤드라인, 서브카피, CTA, 에러·빈 화면 문구)
  - SEO 기본안(제목, 메타 설명, 헤딩 구조)
- 산출물: 사이트맵, 페이지별 섹션 명세, 카피 초안
- 사람이 확인할 것: 사용자 흐름의 타당성, 카피의 브랜드 톤. 고객 컨펌 후 확정한다.

### 단계 6. 스타일 정의와 시안 제작

- AI가 하는 일
  - 브리프 기반 **무드/컨셉 방향 2~3안**의 텍스트 설명과 키워드
  - **디자인 토큰 초안**(컬러 팔레트, 타이포 스케일, 간격, 라운드, 그림자) — 대비 기준을 만족하는지 계산해서 제시
  - 컴포넌트 목록(버튼, 카드, 폼, 네비게이션)과 상태(기본/호버/포커스/비활성/에러) 정의
  - HTML/CSS 기반 **인터랙티브 프로토타입 초안**을 생성해 방향 확인용으로 사용
  - 반복 페이지의 **변형 시안**(모바일/태블릿/데스크톱 규칙 적용) 초안
- 산출물: 스타일 가이드(토큰), 컴포넌트 명세, 시안 초안(Figma 또는 코드 프로토타입)
- 사람이 확인할 것: **시각적 완성도와 브랜드 감각은 디자이너가 직접 한다.** AI 초안은 출발점이고, 그대로 납품하지 않는다.
- 주의: 이미지·아이콘·폰트의 **상업 사용 라이선스**를 확인한다. AI 생성 이미지는 고객 계약 조건(AI 생성물 허용 여부)에 맞춘다.

### 단계 7. 내부 검수 (검수 봇)

납품 전에 사람이 보기 전에 기계적으로 걸러내는 단계. 우리가 앞서 기획한 리뷰 봇이 여기에 들어간다.

- 자동 검사 (코드로 계산, 신뢰도 높음)
  - 텍스트 색 대비(WCAG AA), 최소 글자 크기, 터치 영역 크기
  - 디자인 토큰 외 임의 값 사용 여부, 간격 규칙 위반
  - 페이지 간 컴포넌트 일관성(버튼 높이, 라운드 등)
- AI 검사 (판단 영역, 근거 표시 필수)
  - 요구사항 대비 누락(SOW의 페이지·기능이 시안에 모두 있는지)
  - UX 휴리스틱(위계, 흐름, 피드백), 카피 명확성
  - 상태 누락(로딩, 에러, 빈 화면)
- 산출물: 검수 리포트 (이슈, 심각도, 근거 유형, 수정안), 납품 가능 여부 권고
- 원칙: 지적마다 **근거 유형(측정됨/규칙 위반/휴리스틱/추정)**을 표시하고, 판정은 규칙으로 계산한다. 최종 승인은 사람이 한다.

### 단계 8. 고객 피드백 관리

외주에서 가장 비용이 새는 구간이다.

- AI가 하는 일
  - 고객 피드백 메시지를 **개별 수정 항목으로 분해**하고 각각을 SOW 범위 내/외로 분류
  - 모호한 피드백("좀 더 임팩트 있게")을 **구체 선택지**(A안/B안)로 바꿔 되묻는 문구 생성
  - 상충하는 피드백(담당자마다 다른 요구)을 감지해 정리
  - 수정 이력 로그(요청 → 반영 → 확인) 자동 기록, **수정 횟수 카운트**
  - 범위 밖 요청은 **추가 견적 안내문** 초안
- 산출물: 피드백 처리표(항목, 범위 여부, 담당, 상태), 고객 회신 초안
- 사람이 확인할 것: 범위 밖 요청의 대응(수용/유료화)은 사람이 결정한다. 고객과의 관계 판단이 필요하다.

### 단계 9. 납품과 핸드오프

- AI가 하는 일
  - 시안에서 **개발 핸드오프 문서** 생성: 레이아웃 규칙, 토큰, 컴포넌트 상태, 반응형 기준, 인터랙션 설명, 예외 상태
  - 에셋 목록과 파일명 규칙 정리, 체크리스트 대조
  - 고객용 **납품 안내서**(사용 방법, 수정 가능 범위, 향후 유지보수 안내)
  - 프로젝트 **회고 기록**(소요 시간, 수정 횟수, 잘된 점/개선점)
- 산출물: 핸드오프 스펙, 납품 패키지, 회고 문서
- 효과: 문서 작업을 크게 줄이고 개발자와의 재문의를 줄인다.

### 단계 10. 사후 관리와 자산화

- 완료 프로젝트의 산출물(브리프, IA, 토큰, 컴포넌트, 카피 패턴, 이슈 목록)을 **팀 자산 라이브러리**로 저장
- 다음 문의의 견적 추정과 리서치, 검수 기준에 재사용 (쌓일수록 AI 정확도가 올라간다)
- 포트폴리오용 케이스 스터디 초안 자동 생성(고객 공개 허락 범위 내)

## 3. 만들 자동화 시스템 (구성 요소)

### 3.1 프로젝트 폴더 규약 (가장 먼저, 가장 큰 효과)

모든 프로젝트를 같은 구조로 관리해야 AI가 일관되게 읽고 쓴다.

```
projects/<고객명>_<프로젝트>/
  00_inquiry/      문의 원문, 질문 리스트, 견적 초안
  01_contract/     SOW, 변경 규칙, 계약 요약
  02_brief/        브랜드 요약, 프로젝트 브리프(컨펌본), 회의록
  03_research/     경쟁사 분석, 페르소나, 출처 링크
  04_ia/           사이트맵, 섹션 명세, 카피
  05_design/       토큰, 컴포넌트 명세, 시안 파일, 프로토타입
  06_review/       검수 리포트(버전별)
  07_feedback/     고객 피드백 처리표, 수정 이력
  08_delivery/     핸드오프 문서, 납품 패키지
  99_retro/        회고, 소요 시간 기록
```

### 3.2 단계별 프롬프트 모음 (재사용 스킬)

- 단계마다 입력 형식과 출력 형식을 고정한 **프롬프트 템플릿**을 만든다.
- 팀 공통 규칙(톤, 금지 사항, 출처 표시, 불확실하면 질문)을 시스템 지침으로 넣는다.
- 우선 만들 것 5개: ① 문의 분석·질문 생성 ② SOW 초안 ③ 브리프 정리 ④ 피드백 분해 ⑤ 핸드오프 문서
- 개선 방법: 결과가 마음에 안 들면 프롬프트를 고치고 버전을 기록한다.

### 3.3 검수 봇

- 앞서 기획한 구조 그대로, 입력은 **시안 + SOW + 디자인 토큰**.
- 수치 검사는 코드로, 판단은 AI로, 판정은 규칙으로.
- 역할 관점(기획/개발/디자인)을 분리하면 SOW 충족, 구현 가능성, 시각 품질을 따로 볼 수 있다.

### 3.4 피드백 처리기

- 고객 메시지를 붙여 넣으면 항목 분해, 범위 판정, 회신 초안을 생성.
- SOW와 수정 횟수를 읽어 **현재 몇 번째 수정인지, 범위 밖인지** 알려 준다.

### 3.5 견적·일정 도우미

- 과거 프로젝트의 실제 소요 시간 데이터(페이지 수, 유형별)를 쌓아 견적 근거로 사용.
- 처음에는 데이터가 없으니 스프레드시트로 시작하고, 3~5건 쌓이면 AI가 추정 범위를 제시한다.

### 3.6 납품 문서 생성기

- 시안과 토큰에서 핸드오프 문서와 납품 안내서를 템플릿 기반으로 생성.

### 3.7 자동화 수준

| 수준 | 설명 | 추천 시점 |
|---|---|---|
| L1 수동 | 템플릿을 복사해서 AI 채팅에 붙여 넣기 | 시작 (바로 가능) |
| L2 반자동 | 폴더의 파일을 읽어 AI가 문서를 생성하는 스크립트 | 프로젝트 2~3건 후 |
| L3 연동 | 문의 폼, 메신저, 프로젝트 도구와 연결해 알림·상태 자동 갱신 | 팀이 안정화된 후 |

처음부터 연동(L3)을 만들면 유지보수 부담이 커진다. L1로 효과를 확인한 뒤 올린다.

## 4. 품질 관리와 신뢰성

1. **출처 의무**: 리서치와 사실 주장에는 링크를 붙인다. 링크가 없으면 "추정"으로 표시한다.
2. **측정 가능한 것은 코드로**: 대비, 크기, 간격은 AI 눈대중이 아니라 계산한다.
3. **사람의 승인 지점 고정**: 견적, 계약, 브리프 컨펌, 시안 최종, 납품 — 이 다섯 곳은 반드시 사람이 승인한다.
4. **정답지로 검증**: 과거 프로젝트의 사람 리뷰 결과와 봇 결과를 비교해 오탐/미탐을 측정한다.
5. **프롬프트 버전 관리**: 어떤 버전의 프롬프트로 만든 결과인지 기록한다.

## 5. 법적·윤리적 체크리스트

- [ ] 계약서에 AI 활용 범위와 고지 조항이 있는가
- [ ] 고객 자료를 외부 AI 서비스에 올려도 되는지 확인했는가 (비밀 유지 조항)
- [ ] 사용하는 AI 서비스의 데이터 학습 설정(입력 데이터 학습 제외)을 확인했는가
- [ ] 이미지·아이콘·폰트의 상업 사용 라이선스를 확인했는가
- [ ] 경쟁사·레퍼런스를 모방하지 않고 패턴만 참고했는가
- [ ] AI 생성물의 저작권 귀속과 고객 양도 범위를 계약에 명시했는가
- [ ] 개인정보(고객의 사용자 데이터)를 AI에 입력하지 않았는가

## 6. 도입 로드맵

### 1단계 (1~2주): 접수에서 IA까지 L1 적용
- 폴더 규약과 프롬프트 5종 작성
- 실제 프로젝트 1건에 적용
- 측정: 접수~IA 소요 시간, 질문 리스트로 발견한 누락 요구사항 수

### 2단계 (3~4주): 시안·검수·피드백
- 디자인 토큰 생성 절차, 검수 봇(수치 검사 포함), 피드백 처리기
- 측정: 수정 횟수, 납품 전 발견한 이슈 수

### 3단계 (5~8주): 납품 문서 자동화와 자산화
- 핸드오프 문서 생성기, 회고/자산 라이브러리
- 견적 도우미에 실제 소요 시간 데이터 반영

### 4단계 (이후): 연동 자동화(L3)
- 문의 폼, 메신저, 프로젝트 관리 도구 연결

## 7. 성공 지표

| 지표 | 의미 |
|---|---|
| 프로젝트당 총 작업 시간 | 전체 효율 |
| 단계별 소요 시간 (접수~IA, 시안, 납품) | 어디서 줄었는지 |
| 평균 수정 횟수 | 요구사항 명확화 효과 |
| 범위 밖 요청 비율과 처리 결과 | 분쟁 리스크 |
| 견적 대비 실제 시간 오차 | 견적 정확도 |
| 검수 봇 오탐/미탐률 | 봇 신뢰도 |
| 고객 만족도(재의뢰, 추천) | 품질 |

## 8. 위험과 대응

| 위험 | 대응 |
|---|---|
| AI 결과가 평범하고 비슷해 보임 | 컨셉과 시각 판단은 디자이너가 주도, AI는 탐색 보조로 한정 |
| 고객이 AI 사용에 부정적 | 계약 단계에서 고지·협의, 고객 요구 시 해당 단계 제외 |
| 틀린 정보를 사실처럼 제시 | 출처 의무, 링크 없는 주장 배제 |
| 자료 유출 | 학습 제외 설정 확인, 민감 자료는 입력 금지 또는 비식별화 |
| 도구 의존으로 팀 역량 약화 | 최종 판단과 검수는 사람이 계속 수행, 정기 회고 |
| 시스템 유지보수 부담 | L1에서 시작하고 효과가 확인된 부분만 자동화 |

## 9. 확인이 필요한 사항 (답에 따라 설계가 바뀜)

1. 주력 외주 유형: 랜딩 / 기업 홈페이지 / 쇼핑몰 / 서비스 웹앱
2. 납품 범위: 시안만 / 시안 + 퍼블리싱(코드)
3. 팀 규모와 역할 분담, 사용 중인 도구(Figma, 메신저, 프로젝트 관리)
4. 월 외주 건수와 단가대 (자동화 투자 대비 효과 판단)
5. 과거 프로젝트 자료(브리프, 견적, 소요 시간)의 보유 여부
