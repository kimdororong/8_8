# 디자인 기준서 · 섹션 템플릿 라이브러리 제작 가이드

대상: 상세페이지 자동화 파이프라인(AI → JSON → Figma 플러그인)의 디자인 품질을 책임지는 디자이너
관련 문서: [detail_page_typo_spacing_rules.md](detail_page_typo_spacing_rules.md) (타이포·여백 초안)

## 0. 먼저 이해할 것: 두 문서의 관계

| | 디자인 기준서 | 섹션 템플릿 라이브러리 |
|---|---|---|
| 정체 | **규칙** (숫자와 금지 목록) | **부품** (완성된 섹션 디자인) |
| AI가 쓰는 방식 | 프롬프트의 제약 조건으로 읽음 | 템플릿을 **고르고 내용만 채움** |
| 막아 주는 문제 | 즉흥적이고 들쭉날쭉한 수치 | 백지 생성의 어색한 구성 |
| 만드는 사람의 역할 | 감각을 **숫자로 번역** | 감각을 **직접 디자인** |
| 효과 | 중간 | **가장 큼** (품질 편차의 대부분을 해결) |

둘은 한 세트다. **기준서는 라이브러리를 만들 때의 설계도**이고, 라이브러리는 기준서가 실제로 적용된 결과다. 순서는 기준서 v1 → 라이브러리 → 기준서 v2(라이브러리를 만들며 발견한 것 반영)로 간다.

AI가 하는 일: 초안 작성, 표 정리, 변주 아이디어, 규칙 점검, JSON 변환.
디자이너가 하는 일: **취향과 판단(무엇이 좋은가)을 결정**하고 Figma에서 섹션을 직접 다듬는 것. 이 부분은 AI가 대신할 수 없고, 바로 이게 결과물의 퀄리티를 결정한다.

# 파트 1. 디자인 기준서 만들기

## 1-1. 목표와 범위 정하기 (1시간)
먼저 아래 5개를 한 문장씩 적는다. 이게 기준서의 방향타다.

| 질문 | 예시 |
|---|---|
| 어떤 상품 카테고리를 대상으로 하나 | 식품 / 뷰티 / 생활용품 중 1~2개로 시작 |
| 어떤 분위기를 목표로 하나 | 깔끔한 미니멀 / 신뢰감 있는 정보형 / 감성 사진형 |
| 누가 보나 | 모바일로 보는 20~40대 |
| 판매처와 규격 | 카페24·스마트스토어, 폭 860px(가정) |
| "합격선"은 어디인가 | 채점표 28점 이상 |

**카테고리를 처음부터 넓히지 않는다.** 식품이면 식품에 맞는 기준서를 먼저 만들고, 뷰티는 나중에 복제해서 고친다.

## 1-2. 레퍼런스 수집과 분석 (2~3시간)
"좋은 상세페이지"를 AI에게 설명하는 대신, 직접 모아서 **왜 좋은지를 규칙으로 뽑는다.**

**수집**
- 카테고리별로 잘 만든 상세페이지 10~20개를 모은다 (본인이 보고 "퀄리티 좋다"고 느낀 것).
- 반대로 **"구리다"고 느낀 것도 5개** 모은다. 대비가 있어야 기준이 선명해진다.
- 저작권: 분석용으로만 보고, **복제하거나 템플릿에 그대로 넣지 않는다.** 규칙(수치, 구성, 리듬)만 추출한다.

**분석 방법 (표로 정리, 이 부분을 AI가 도와줄 수 있다)**
스크린샷을 AI에게 보여 주고 아래 표를 채우게 한 뒤, 디자이너가 틀린 곳을 고친다.

| 항목 | 기록할 것 | 예시 |
|---|---|---|
| 섹션 순서 | 위에서 아래 구성 | 히어로 → 공감 → 특징 3 → 사용법 → 후기 → FAQ |
| 글자 크기 | 제목/본문의 상대 비율 | 제목이 본문의 약 2배 |
| 글 분량 | 섹션당 글자 수 | 보통 60~120자 |
| 여백 | 섹션 간 여백의 느낌 | 넉넉함 (본문 높이의 1.5배) |
| 색 | 주색·보조색·배경 | 베이지 배경 + 진갈색 글자 |
| 리듬 | 빽빽한 섹션과 여유 섹션의 교차 | 글 → 사진 → 글 |
| 시선 흐름 | 어디서 멈추게 하는가 | 큰 숫자, 아이콘 |
| 좋은 점 / 거슬리는 점 | 한 줄 | 정보 위계가 분명 / 하단 표 글자가 작음 |

**결과물**: 레퍼런스 분석표 1장 + "공통으로 보이는 패턴" 10줄 요약. 이게 기준서의 근거가 된다.

> 팁: 분석표를 채울 때 AI에게 "수치는 추정이라고 표시"하게 한다. 스크린샷에서 정확한 px을 읽을 수는 없으므로, 비율(상대적 크기)로 기록하고 실제 px은 직접 제작하며 정한다.

## 1-3. 토큰 정의 (2~3시간)
**토큰 = 디자인의 기본 값 모음.** 이것만 정해 두면 규칙의 70%가 끝난다.

| 토큰 종류 | 정할 것 | 예시 |
|---|---|---|
| 타입 | 서체, 굵기, 크기 스케일, 줄간격, 자간 | (이미 만든 타이포 기준서 사용) |
| 간격 | 8px 그리드와 허용 값 | 8/16/24/32/48/64/80/120/160 |
| 색 | 주색 1, 보조색 1, 무채색 5단계, 배경 2종, 강조색 | 팔레트와 용도별 이름 |
| 모서리 | 라운드 값 | 0 / 8 / 16 / 999(완전 둥글게) 중 택1~2 |
| 그림자 | 사용 여부와 단계 | 없음 또는 1~2단계 |
| 이미지 | 허용 비율, 모서리 처리, 오버레이 | 1:1, 4:3, 16:9 / 오버레이 40% |

**색 팔레트 작업 방법**
1. 카테고리 분위기에 맞는 주색을 정한다 (예: 식품 → 따뜻한 갈색/주황 계열).
2. 대비 4.5:1을 통과하는 글자색/배경색 **조합 표**를 만든다 (조합이 정해지면 AI가 임의로 섞을 수 없다).
3. 팔레트를 **2~3종 세트**(예: 따뜻한 / 차분한 / 선명한)로 만들어 두고, AI는 세트 중 하나를 고르게 한다.

**Figma에서 하는 일**: 위 값을 Figma **변수(Variables)와 스타일**로 등록한다. 이게 라이브러리와 파이프라인의 공통 기반이 된다.

## 1-4. 규칙 작성 (3~4시간)
규칙은 **측정 가능하게** 쓴다. "여백을 넉넉하게"가 아니라 "섹션 위아래 120px".

**규칙 문장의 형식**
```
[규칙 ID] 규칙 내용 (수치) — 이유 — 예외
예) S3. 좌우 여백은 60px 고정 — 모바일에서 글자가 가장자리에 붙으면 답답해 보임 — 풀폭 이미지는 예외
```

**반드시 포함할 6가지 범주**
1. 타이포 (이미 초안 있음)
2. 간격·여백 (이미 초안 있음)
3. 색·대비
4. 이미지 (비율, 해상도, 글자 얹는 법)
5. 섹션 구성 (순서, 분량, 리듬)
6. **금지 목록** (아래)

**금지 목록은 가장 효과가 크다.** AI는 "하지 마"에 잘 반응한다. 구린 레퍼런스 5개와 실제 결과물에서 거슬린 것을 그대로 금지 항목으로 만든다.
- 예: 글자 24px 미만 / 사진 위 글자에 오버레이 없음 / 한 섹션에 강조 2종 이상 / 장식용 선·도형 남발 / 이모지 남용 / 임의 그라디언트

**AI가 도와주는 부분**: 분석표에서 규칙 후보를 뽑고, 규칙을 문장 형식으로 정리하고, 규칙 간 모순(예: 글자 크기와 줄 폭이 충돌)을 점검한다.

## 1-5. 시험 제작으로 규칙 검증 (3~4시간)
규칙은 종이 위에서는 다 좋아 보인다. **실제로 만들어 봐야 틀린 곳이 보인다.**
1. 규칙만 지켜서 **샘플 섹션 5개**(히어로, 특징, 사용법, 후기, FAQ)를 Figma에서 직접 만든다.
2. 만들면서 "이 규칙이 답답하다/부족하다"를 기록한다.
3. 규칙을 수정해 v0.2로 올린다.

이 단계를 건너뛰면 기준서가 이론에 머문다.

## 1-6. AI 지침으로 변환 (1시간)
기준서 전체를 AI에게 주면 길어서 일부가 무시된다. **핵심만 압축한 지침**을 따로 만든다.
- 길이: A4 1장 이내, 숫자 중심
- 구조: ① 절대 규칙(위반 금지) ② 선택 규칙(권장) ③ 금지 목록 ④ 막혔을 때의 행동("지킬 수 없으면 임의로 어기지 말고 문구를 줄이거나 섹션을 나눌 것")
- 이미 만든 타이포·여백 문서의 4번 블록이 이 형식의 예시다.

## 1-7. 버전 관리 (계속)
- 파일 맨 위에 **버전과 변경 이력**을 둔다 (v0.1 → v0.2 …).
- 규칙을 바꿀 때는 **이유를 한 줄** 적는다 ("본문 28→30px: 모바일에서 작아 보여서").
- 규칙 바꾸기 전에 **같은 상품으로 전/후 비교**를 한다 (채점표 사용).

## 1-8. 기준서 완성 체크리스트
- [ ] 목표·범위 5문장이 있다
- [ ] 레퍼런스 분석표와 공통 패턴 10줄이 있다
- [ ] 토큰(타입/간격/색/모서리/그림자/이미지)이 Figma 변수로 등록돼 있다
- [ ] 6범주 규칙이 측정 가능한 문장으로 쓰여 있다
- [ ] 금지 목록이 10개 이상 있다
- [ ] 직접 만든 샘플 5개로 검증했다
- [ ] A4 1장 AI 지침이 있다
- [ ] 버전과 변경 이력이 있다
- [ ] 폰트·이미지 라이선스를 확인했다

**예상 소요: 약 13~18시간** (레퍼런스 수집, 토큰, 규칙, 시험 제작). 한 번에 몰아서 하지 말고 1~2주에 나눠서 한다. 시간은 추정치이고, 이미 가진 감각과 자료에 따라 달라진다.

# 파트 2. 섹션 템플릿 라이브러리 만들기

## 2-1. 라이브러리의 구조 이해

**템플릿 1개 = 아래 4가지의 묶음**
1. **Figma 컴포넌트**: 실제 디자인 (오토레이아웃, 변수 사용)
2. **슬롯 정의**: 바뀌는 부분의 목록과 제약 (글자 수, 이미지 비율 등)
3. **변주(variant)**: 같은 섹션의 다른 모양 2~3종
4. **사용 규칙**: 언제 쓰고 언제 쓰지 않는지

AI는 **"이 상품에는 이 섹션을 이 순서로 쓰고, 슬롯에 이 내용을 넣겠다"** 만 결정한다. 디자인 자체는 건드리지 않는다. 이게 "백지 생성"보다 퀄리티가 안정되는 이유다.

## 2-2. 섹션 인벤토리 (무엇을 만들까) — 약 1시간

상세페이지에 자주 쓰이는 섹션 목록이다. 처음에는 **필수 10개**만 만든다.

| # | 섹션 | 역할 | 우선순위 |
|---|---|---|---|
| 1 | 히어로 | 첫 화면. 핵심 약속 + 상품 | 필수 |
| 2 | 공감·문제 제기 | "이런 고민 있으셨죠" | 필수 |
| 3 | 핵심 특징 3 (3-point) | 특징 3가지 요약 | 필수 |
| 4 | 상세 특징 (이미지+글 지그재그) | 특징 하나를 크게 설명 | 필수 |
| 5 | 사용법 (스텝) | 1-2-3 단계 설명 | 필수 |
| 6 | 후기·리뷰 | 사회적 증거 | 필수 |
| 7 | 스펙·정보 표 | 규격, 성분, 영양 | 필수 |
| 8 | FAQ | 자주 묻는 질문 | 필수 |
| 9 | 배송·교환·환불 안내 | 법정 고지 포함 | 필수 |
| 10 | 마무리 CTA | 구매 유도 | 필수 |
| 11 | 비교·차별점 표 | 일반 제품 대비 | 선택 |
| 12 | 신뢰 요소 (인증·수상·수치) | 숫자·로고 | 선택 |
| 13 | 구성품 | 포함된 것 | 선택 |
| 14 | 타이틀 밴드(구분 제목) | 섹션 전환 | 선택 |
| 15 | 카테고리 특화 (성분·원료 / 소재 / 사이즈 가이드) | 카테고리별 | 선택 |

## 2-3. 섹션별 명세 카드 작성 — 섹션당 약 30분

Figma로 만들기 **전에** 먼저 카드를 쓴다. 이게 설계도이고, AI와 팀원 모두가 읽는 기준이다.

```
■ 섹션 이름: 핵심 특징 3 (feature-3)
■ 역할: 특징 3가지를 한눈에 보여 준다
■ 언제 쓰는가: 상품의 핵심 장점이 3개로 정리될 때 / 쓰지 않는 경우: 장점이 2개 이하 또는 5개 이상
■ 슬롯
  - section_title  : 텍스트, 1줄, 8~16자
  - item[3].icon   : 이미지(아이콘), 정사각, 96x96
  - item[3].title  : 텍스트, 1줄, 6~12자
  - item[3].body   : 텍스트, 2~3줄, 30~60자
■ 변주
  - A: 가로 3열 카드 (모바일 줄임 시 가독성 낮아 비추)
  - B: 세로 3행 리스트 (기본)
  - C: 숫자 강조형 (01/02/03)
■ 배경: 흰색 또는 연한 무채색 (인접 섹션과 달라야 함)
■ 사용 토큰: 간격 120(위아래), 카드 간격 24, 카드 안쪽 40
■ 제약
  - 글자 크기 스케일 값만 사용
  - 슬롯 글자 수를 넘으면 문구를 줄여서 채울 것 (임의 축소 금지)
■ 이미지 없을 때: 아이콘 대신 숫자 표시로 대체
■ 긴 텍스트·짧은 텍스트 시험 통과 여부: [ ]
```

**슬롯 정의가 핵심이다.**
- 글자 수 상한과 하한을 **반드시** 정한다. AI가 글을 길게 쓰면 넘치는 문제가 여기서 막힌다.
- 이미지는 **비율과 최소 해상도**를 정한다.
- 비어 있을 때(이미지 없음, 항목 2개)의 **대체 동작**을 정한다.

## 2-4. Figma에서 만들기 — 섹션당 1~2시간

### 파일 구조
```
[파일] Detail-Page-Library
  페이지 0. README        사용법, 버전, 변경 이력, 네이밍 규칙
  페이지 1. Tokens        색·타입·간격 변수 (확인용 샘플)
  페이지 2. Sections      컴포넌트 (여기가 라이브러리 본체)
  페이지 3. Samples       조합 샘플 (시험용 완성 페이지)
  페이지 4. Tests         긴 텍스트/짧은 텍스트/이미지 없음 시험
```

### 제작 원칙 (판매용 템플릿에도 그대로 쓰이는 원칙)
1. **캔버스 폭 860으로 고정**한 프레임에서 시작한다.
2. **모든 값은 변수(토큰)** 를 쓴다. 색·글자 크기·간격을 직접 숫자로 입력하지 않는다.
3. **오토레이아웃 필수**: 글자가 늘어나면 섹션 높이가 따라 늘어나게 만든다. 고정 높이 금지.
4. **레이어 이름은 역할로**: `feature-3 / item / title`처럼 슬롯 이름과 똑같이. `Rectangle 47` 금지. (파이프라인이 이름으로 슬롯을 찾기 때문에 중요하다)
5. **컴포넌트로 만들고 변주는 variant로** 묶는다.
6. 텍스트는 **슬롯 이름의 레이어**에 두고, 장식 요소와 분리한다.
7. 숨은 레이어, 빈 그룹, 쓰지 않는 요소를 남기지 않는다.

### 네이밍 규칙 예시
```
섹션:    sec/{섹션이름}/{변주}          예) sec/feature-3/B
슬롯:    {섹션}.{슬롯}[인덱스]          예) feature-3.item[1].title
토큰:    color/primary, type/body, space/section
```
이 규칙을 팀원과 합의해서 **JSON의 필드 이름과 일치**시킨다 (아래 2-7).

### 변주 만드는 법
- 한 섹션당 **2~3종**이면 충분하다. 너무 많으면 AI의 선택이 흔들린다.
- 변주 사이의 **차이는 레이아웃(배치)** 에서 만들고, 타입·간격·색 규칙은 모두 동일하게 유지한다.
- 변주마다 "추천 상황"을 한 줄 적는다 (예: B는 글이 길 때, C는 숫자가 중요할 때).

## 2-5. 스트레스 테스트 — 섹션당 20분 (가장 많이 건너뛰는데 가장 중요)

각 섹션을 아래 상황으로 시험한다. 하나라도 깨지면 수정한다.

| 시험 | 방법 | 합격 기준 |
|---|---|---|
| 긴 텍스트 | 슬롯 상한의 1.5배 글자를 넣는다 | 레이아웃이 안 깨지거나, 깨지면 "상한 초과"로 명확히 알 수 있다 |
| 짧은 텍스트 | 슬롯 하한의 절반으로 넣는다 | 휑하지 않고 균형이 유지된다 |
| 이미지 없음 | 이미지를 제거한다 | 대체 동작대로 보인다 |
| 항목 수 변화 | 3개 항목을 2개, 4개로 | 정렬이 유지되거나 사용 금지 조건이 명시돼 있다 |
| 모바일 축소 | 폭 390px 정도로 줄여 본다 | 글자가 읽힌다 (24px 이상 유지) |
| 색 조합 교체 | 팔레트 세트 3종을 바꿔 넣는다 | 대비가 모두 통과한다 |
| 한글/숫자/영문 혼합 | 섞인 문구를 넣는다 | 줄바꿈이 어색하지 않다 |

## 2-6. 섹션 조합(시퀀스) 규칙 — 2시간

섹션 하나하나가 좋아도 **순서와 조합**이 나쁘면 페이지가 구려진다. AI가 순서를 고르게 하려면 규칙이 필요하다.

**기본 시퀀스 (예시, 식품 카테고리)**
```
히어로 → 공감 → 핵심 특징 3 → 상세 특징(지그재그) × 2~3 → 신뢰 요소
→ 사용법/먹는 법 → 후기 → 스펙·영양 표 → FAQ → 배송·교환 → 마무리 CTA
```

**조합 규칙 예시**
1. 첫 섹션은 반드시 히어로, 마지막은 배송·교환 + CTA.
2. 글이 많은 섹션(공감, 사용법, FAQ)이 **연속 2개를 넘지 않는다.**
3. 지그재그 섹션은 좌-우를 번갈아 배치한다.
4. 같은 변주는 **연속으로 쓰지 않는다.**
5. 배경색은 인접 섹션과 달라야 하며, 페이지 전체에서 3종 이하.
6. 페이지 길이: 섹션 수 **10~14개** 권장.

시퀀스는 카테고리별로 2~3종을 미리 정의해 두고, AI는 상품 정보에 맞춰 그중 하나를 고르거나 선택 섹션을 넣고 뺀다.

## 2-7. 팀원 파이프라인과 연결 — 팀원과 협의

**팀원에게 확인할 것 (이 정보가 있어야 맞게 만들 수 있다)**
1. 현재 JSON의 구조: 섹션이 어떤 필드로 표현되는가
2. Figma 플러그인이 JSON을 어떻게 그리는가 (노드를 새로 만드나, 기존 컴포넌트를 불러오나)
3. 글자 크기·색을 JSON에서 숫자로 지정하나, 토큰 이름으로 지정하나

**연결 방식 두 가지 (결정은 팀원과 함께)**
| 방식 | 설명 | 장단점 |
|---|---|---|
| **컴포넌트 불러오기형 (추천)** | JSON은 "어떤 섹션, 어떤 변주, 슬롯 값"만 지정. 플러그인이 Figma 라이브러리의 컴포넌트를 불러와 슬롯을 채움 | 디자이너가 만든 디자인이 그대로 나와 퀄리티가 안정적. 플러그인 수정 필요 |
| **수치 지정형** | JSON이 글자 크기·간격 등을 직접 숫자로 지정, 플러그인이 새로 그림 | 구현은 단순하지만 AI가 수치를 틀리면 퀄리티가 흔들림. 이 경우 기준서의 점검 규칙이 필수 |

현재가 수치 지정형이라면 **컴포넌트 불러오기형으로 전환하는 게 퀄리티 개선의 가장 큰 단일 조치**일 가능성이 높다 (JSON을 보기 전이라 단정은 아님). 팀원에게 이 제안을 가져가 본다.

**JSON 명세 예시 (연결 시 목표 형태, 실제 필드는 팀원 구조에 맞춤)**
```json
{
  "palette": "warm",
  "sections": [
    { "type": "hero", "variant": "A",
      "slots": { "title": "...", "subtitle": "...", "image": "product_01" } },
    { "type": "feature-3", "variant": "B",
      "slots": { "section_title": "...",
                 "items": [ { "title": "...", "body": "..." }, ... ] } }
  ]
}
```
AI는 이 JSON만 만든다. 디자인(모양)은 라이브러리가 결정한다.

**검증 단계 추가**: 생성된 JSON이 슬롯 제약(글자 수, 항목 수)을 지키는지 코드로 검사하고, 어기면 AI에게 다시 만들게 한다. 슬롯 명세 카드가 이 검사 규칙의 원천이다.

## 2-8. 라이브러리 확장과 유지보수

**확장 순서**
1. 필수 10개 섹션 × 변주 2종 = 20개 컴포넌트로 시작
2. 실제 상품 5~10개로 생성해 보며 **"자주 필요한데 없는 섹션"** 을 기록
3. 그 섹션을 추가 (데이터 기반으로 늘린다. 미리 많이 만들지 않는다)
4. 다른 카테고리는 **팔레트 세트와 카테고리 특화 섹션**만 추가하고 나머지는 재사용

**버전 관리**
- 라이브러리 파일에 버전 번호와 변경 이력을 둔다.
- 컴포넌트 수정 시 **이전 결과물이 깨지지 않는지** 샘플 페이지로 확인한다.

**품질 지표**
- 채점표 평균 점수 (기준서와 동일한 표)
- 슬롯 제약 위반 비율 (AI가 글자 수를 넘기는 빈도)
- 사람이 수정한 섹션 비율 (수정이 잦은 섹션이 개선 대상)

## 2-9. 라이브러리 완성 체크리스트
- [ ] 섹션 인벤토리와 우선순위가 있다
- [ ] 필수 10개 섹션의 명세 카드가 있다 (슬롯·제약·변주·사용 조건)
- [ ] Figma 컴포넌트가 오토레이아웃과 변수로 만들어졌다
- [ ] 레이어 이름이 슬롯 이름 규칙과 일치한다
- [ ] 변주가 섹션당 2~3종이다
- [ ] 스트레스 테스트 7종을 모두 통과했다
- [ ] 카테고리별 시퀀스 규칙이 있다
- [ ] 팀원 JSON·플러그인과 연결 방식을 합의했다
- [ ] 샘플 페이지 3개를 조합해서 채점표 28점 이상을 확인했다
- [ ] 폰트·이미지·아이콘의 라이선스를 확인했다

**예상 소요: 약 25~40시간** (필수 10개 섹션 × 변주 포함, 명세 카드와 시험 포함). 마찬가지로 추정치다. 한 번에 만들지 말고 **섹션 3개 → 시험 조합 → 나머지 순서**로 가면 중간에 방향을 고칠 수 있다.

# 파트 3. 전체 진행 순서 (권장)

| 주차 | 할 일 | 산출물 |
|---|---|---|
| 1주 | 목표·범위, 레퍼런스 분석, 토큰 정의 | 분석표, 토큰(Figma 변수) |
| 1~2주 | 규칙 작성, 시험 제작 5섹션, 기준서 v0.2, AI 지침 | 기준서 v0.2, 지침 1장 |
| 2주 | **팀원과 연결 방식 협의**, 팀원 프로그램에 지침 적용, 전/후 비교 | 전/후 채점 결과 |
| 2~4주 | 섹션 명세 카드, Figma 컴포넌트 3개 → 10개 | 라이브러리 v0.1 |
| 4주 | 스트레스 테스트, 시퀀스 규칙, 샘플 페이지 조합 | 라이브러리 v0.2, 샘플 3개 |
| 5주~ | 실제 상품으로 생성·검수, 부족한 섹션 추가, 기준서 v1.0 | 안정화 |

**중간에 효과를 확인하는 지점**
- 2주 차: 지침만 적용했는데 채점표 점수가 올랐는가? (기준서의 효과)
- 4주 차: 라이브러리 연결 후 점수가 더 올랐는가? (라이브러리의 효과)
이 숫자가 안 오르면 방향을 바꿔야 한다. 아무 측정 없이 계속 만들면 소용이 없다.

## 주의할 점
1. **한 번에 완벽하게 만들려 하지 않는다.** 섹션 3개만 먼저 만들어 파이프라인에 올려 보는 편이 빠르다.
2. **취향을 숫자로 옮기는 게 가장 어렵고 가장 중요하다.** 막히면 좋은 레퍼런스 옆에 자기 결과물을 놓고 "무엇이 다른가"를 적어 규칙으로 바꾼다.
3. 라이브러리 디자인이 **다 비슷한 페이지**를 낳을 수 있다. 팔레트 세트, 변주, 카테고리별 특화 섹션으로 다양성을 확보한다.
4. 판매용으로 쓸 거라면 **폰트·아이콘·이미지 라이선스**를 라이브러리 단계에서 정리한다. 나중에 고치기 어렵다.
5. 이 문서의 시간과 수치는 모두 **초기 추정**이다. 실제로 해 보고 조정한다.
