# AI에 먹일 지침 v0.2-draft (팀원 프로그램 프롬프트용)

근거: [디자인 기준서 v0.2 초안](design_standard_v0.2_draft.md) — 레퍼런스 1건(가전) 기반의 **임시 값**이다. 전/후 채점으로 검증하며 조정한다.

## 사용 순서

| 단계 | 넣을 것 | 목적 |
|---|---|---|
| 1 | **라이트 버전** | 효과가 있는지 가장 적은 규칙으로 확인 |
| 2 | 효과가 있으면 **풀 버전** | 권장 규칙까지 추가해 추가 개선 확인 |
| 3 | 어긴 규칙이 반복되면 | 표현을 바꾸거나 JSON 자동 검사(기준서 9장)로 이동 |

시작 전 팀원에게 확인할 것:
- JSON에서 크기·간격의 **단위**가 px인지, 캔버스 폭이 860인지 (다르면 아래 수치를 860 대비 비율로 환산)
- 크기·색을 숫자로 지정하는지, 토큰 이름으로 지정하는지

---

## A. 라이트 버전 (먼저 시험)

```
[상세페이지 디자인 규칙]
아래 규칙은 반드시 지킨다. 규칙과 충돌하면 규칙이 우선한다.
수치는 캔버스 폭 860px 기준 px이다.

1. 글자 크기는 이 값만 사용한다.
   제목 72/64, 부제 44/40/36, 본문 38/34, 보조 본문 32/28, 캡션·표 30/26.
   24px 미만은 금지한다. 본문은 32px 이상(권장 34~38).
2. 본문 줄간격은 1.4, 제목 줄간격은 1.25로 한다.
3. 글 블록의 최대 폭은 624px, 가운데 정렬이다.
4. 간격은 이 값만 사용한다: 8/16/24/32/48/64/72/80/120/160/200/240.
5. 특징 블록 간격: 섹션 위 240, 번호·라벨→제목 64, 제목→본문 72.
6. 같은 그룹 안의 간격은 그룹 사이 간격의 1/3 이하로 한다.
7. 글자색은 #323232 한 가지(어두운 배경은 #FFFFFF)로 하고, 순검정(#000)은 쓰지 않는다.
   강조는 굵기로만 한다.
8. 서체는 1종, 굵기는 400/600/700만 쓴다.
9. 사진 위에 글자를 얹을 때는 반드시 어두운 오버레이나 단색 박스를 깐다.

금지:
- 임의의 글자 크기·간격 값
- 한 섹션에 강조 2종 이상
- 글이 박스를 넘치게 두기
- 근거 없는 인증·검사·수치 문구를 지어내서 쓰기

규칙을 지킬 수 없으면 어기지 말고 문구를 줄이거나 섹션을 나눠서 해결한다.
그래도 안 되면 어떤 규칙 때문에 막혔는지 한 줄로 알린다.
```

## B. 풀 버전 (라이트 효과 확인 후)

```
[상세페이지 디자인 규칙 v0.2-draft]
아래 규칙은 반드시 지킨다. 규칙과 충돌하면 규칙이 우선한다.
수치는 캔버스 폭 860px 기준 px이다.

■ 1. 절대 규칙
- 캔버스 폭 860px. 모든 이미지·섹션 폭은 860으로 통일한다.
- 글 블록 최대 폭 624px, 가운데 정렬. 이미지·카드의 좌우 여백은 64px.
- 글자 크기는 이 값만 사용한다:
  제목 72/64, 부제 44/40/36, 본문 38/34, 보조 본문 32/28, 캡션·표 30/26(표·정책은 26 이상 권장).
- 24px 미만 글자 금지. 본문은 32px 이상(권장 34~38).
- 서체는 1종, 굵기는 400/600/700만 사용한다.
- 간격은 이 값만 사용한다: 8/16/24/32/48/64/72/80/120/160/200/240.
- 특징 블록 간격: 섹션 위 240, 번호·라벨→제목 64, 제목→본문 72.
- 같은 그룹 안의 간격은 그룹 사이 간격의 1/3 이하로 한다.
- 글자색은 #323232 한 가지(어두운 배경에서는 #FFFFFF). 순검정 금지. 강조는 굵기로만 한다.
- 본문 대비 4.5:1 이상(권장 7:1). 사진 위 글자는 오버레이나 단색 박스를 깐다.

■ 2. 권장 규칙
- 줄간격: 제목 1.25, 본문 1.4.
- 본문 한 블록은 2~3줄. 한 줄은 한글 16~19자. 어절 단위로 줄바꿈하고,
  마지막 줄에 1~2글자만 남기지 않는다.
- 가운데 정렬은 3줄 이하일 때만. 사용법·표·정책은 왼쪽 정렬.
- 특징 섹션은 [번호 + 1줄 제목 + 2~3줄 본문] 구조로, 60~100자, 메시지 1개.
- 글 블록과 사진 섹션을 번갈아 배치한다. 같은 장점은 요약 1번, 상세 1번까지만 쓴다.
- 배경은 3계열(뉴트럴·웜·쿨) 이하. 긴 페이지에는 다크 섹션을 1/4, 3/4 지점에 넣는다.

■ 3. 금지
- 임의의 글자 크기·간격, 두 가지 이상의 서체, 순검정 본문
- 한 섹션에 강조 2종 이상, 글자색 2종 초과
- 같은 장점 3번 이상 반복, 이미지 폭 불일치
- 오탈자·띄어쓰기·약어 철자 오류
- 근거 없는 인증·검사·수치 문구를 지어내서 쓰기
- 장식 도형·이모지 남발, 글이 박스를 넘치게 두기

■ 4. 출력 전 자체 점검
출력하기 전에 아래를 확인하고, 어긴 것이 있으면 고쳐서 출력한다.
- 24px 미만 글자가 있는가 / 허용 값 밖의 크기·간격이 있는가
- 본문이 32px 미만인가 / 글 블록이 624px를 넘는가
- 한 섹션에 강조가 2종 이상인가 / 글자색이 허용 밖인가
- 사진 위 글자에 오버레이가 없는가
- 같은 장점이 3번 이상 나오는가

■ 5. 규칙을 지킬 수 없을 때
- 규칙을 어기지 말고 문구를 줄이거나 섹션을 나눠서 해결한다.
- 그래도 안 되면 어떤 규칙 때문에 막혔는지 한 줄로 알린다.
```

## C. 전/후 비교 방법

1. 같은 상품 정보로 **지침 없이 2회**, **라이트 2회**, **풀 2회** 생성한다 (우연을 줄이기 위해 반복).
2. 결과에 A/B/C 라벨을 가리고, 본인이 먼저 "나은 순서"를 고른 뒤 채점표(7항목×5점)로 점수를 매긴다.
3. 어긴 규칙을 기록한다. 기록 양식:

| 생성 | 버전 | 점수 | 어긴 규칙 | 메모 |
|---|---|---|---|---|
| 1 | 없음 | | | |
| 2 | 라이트 | | | |
| 3 | 풀 | | | |

4. 해석:
   - 점수가 오르면 이 방향이 맞다. 레퍼런스를 더 모아 수치를 다듬는다.
   - 변화가 없으면 AI가 지침을 안 따랐는지(어긴 규칙 확인), 문제가 타이포·여백이 아닌지 확인한다.
   - 나빠지면 수치를 하나씩 줄여 가며 원인 규칙을 찾는다.

## D. 주의
- 이 수치는 **가전 상품 1건**에서 나왔다. 식품·뷰티 등에서는 맞지 않을 수 있다.
- "근거 없는 문구 금지" 규칙은 법적 위험(허위 인증·검사 문구)을 막기 위한 것이다. 상품 정보에 없는 사실은 AI가 만들지 않도록 입력 정보를 충분히 줘야 한다.
- 지침이 길수록 일부가 무시된다. 효과가 약하면 라이트 버전으로 줄여 본다.
